## 1. Общие сведения о проекте

Данный программный комплекс предназначен для автоматической генерации трёхмерных моделей зданий и помещений на основе набора фотографий. Система реализует полный цикл фотограмметрической обработки: от загрузки изображений до получения готовой 3D-модели в формате, пригодном для просмотра в веб-браузере или в специализированном программном обеспечении.

Комплекс построен на базе библиотеки **COLMAP** — специализированной системы для Structure-from-Motion (SfM) и Multi-View Stereo (MVS) реконструкции, и предоставляет как консольный, так и графический интерфейс пользователя.

---

## 2. Цель и задачи

**Цель проекта:** автоматизировать процесс создания трёхмерных моделей реальных объектов (зданий, помещений) на основе обычных фотографий без применения специализированного оборудования (лазерных сканеров, LiDAR и т.д.).

**Задачи, решаемые комплексом:**

- Извлечение ключевых точек (features) из набора входных фотографий.
- Поиск совпадений между фотографиями для определения пространственных взаимосвязей.
- Разреженная 3D-реконструкция сцены методом SfM (Structure-from-Motion).
- Плотная 3D-реконструкция с применением алгоритма PatchMatch Stereo.
- Слияние плотных карт глубины в единое облако точек.
- Построение полигональной сетки (mesh) методом Poisson Surface Reconstruction.
- Конвертация модели в форматы PLY и GLB для дальнейшего использования.
- Предоставление удобного графического интерфейса для управления всеми этапами.

## 4. Архитектура проекта

Проект организован по модульному принципу. Каждый модуль отвечает за строго определённый этап обработки, что обеспечивает простоту сопровождения и возможность независимого запуска отдельных этапов.

```
3Dbuilding/
│
├── main.py                   # Консольный запуск (SfM)
├── main_gui.py               # Графический интерфейс
│
├── src/
│   ├── colmap_runner.py      # Обёртка над COLMAP CLI
│   ├── dense_reconstruction.py  # Плотная реконструкция
│   ├── meshing.py            # Построение полигональной сетки
│   └── converter_ply_to_glb.py  # Конвертация PLY → GLB
│
├── data/
│   ├── images/               # Входные фотографии
│   ├── database.db           # База данных COLMAP
│   ├── sparse/               # Разреженная реконструкция
│   └── dense/                # Плотная реконструкция и модели
│
└── ui/
    └── menu.ui               # Файл разметки GUI (Qt Designer)
```

Центральным элементом системы является класс `ColmapRunner`, который инкапсулирует все обращения к внешнему исполняемому файлу COLMAP. Остальные модули используют его как зависимость.

## 5. Описание модулей

### 5.1 Модуль запуска COLMAP — `colmap_runner.py`

Файл: `src/colmap_runner.py`

Данный модуль содержит класс `ColmapRunner`, который является обёрткой (wrapper) над командной строкой COLMAP. Весь низкоуровневый вызов внешних процессов сосредоточен здесь, что изолирует остальные модули от деталей вызова COLMAP.

#### Инициализация класса

```python
def __init__(self):
    self.colmap_path = r"C:\Users\...\COLMAP.bat"
    self.env = os.environ.copy()
    self.env["COLMAP_NO_GUI"] = "1"
```

При инициализации задаётся путь к исполняемому bat-файлу COLMAP и формируется копия переменных окружения, в которую добавляется `COLMAP_NO_GUI=1`. Этот флаг запрещает COLMAP открывать собственное графическое окно при запуске, что необходимо для работы в режиме командной строки.

#### Метод `_run(cmd_list)`

```python
def _run(self, cmd_list):
    cmd = " ".join(cmd_list)
    subprocess.run(cmd, check=True, env=self.env, shell=True)
```

Приватный метод, выполняющий любую команду COLMAP. Список аргументов преобразуется в строку, поскольку `.bat`-файлы на платформе Windows не могут быть запущены через список аргументов — только через строку с `shell=True`. Параметр `check=True` обеспечивает автоматическое возбуждение исключения при ненулевом коде возврата процесса.

#### Метод `run_feature_extractor(database_path, image_path)`

Выполняет первый этап реконструкции — **извлечение признаков (feature extraction)**. Анализирует каждое изображение из `image_path`, находит ключевые точки (SIFT-дескрипторы) и записывает результаты в базу данных `database_path`.

```python
def run_feature_extractor(self, database_path, image_path):
    cmd = [
        self.colmap_path,
        "feature_extractor",
        "--database_path", f"\"{database_path}\"",
        "--image_path", f"\"{image_path}\"",
    ]
    self._run(cmd)
```

#### Метод `run_matcher(database_path)`

Выполняет **сопоставление признаков (feature matching)** между всеми парами изображений методом `exhaustive_matcher` — каждое изображение сопоставляется с каждым. Результат записывается в ту же базу данных. Этот метод подходит для небольших наборов изображений (до нескольких сотен).

```python
def run_matcher(self, database_path):
    cmd = [
        self.colmap_path,
        "exhaustive_matcher",
        "--database_path", f"\"{database_path}\"",
    ]
    self._run(cmd)
```

#### Метод `run_mapper(database_path, image_path, output_path)`

Выполняет **разреженную 3D-реконструкцию (SfM mapping)**. На основе найденных совпадений восстанавливает положение камер в пространстве и строит разреженное облако точек. Результат сохраняется в директорию `output_path` в виде бинарных файлов COLMAP (`cameras.bin`, `images.bin`, `points3D.bin`).

```python
def run_mapper(self, database_path, image_path, output_path):
    cmd = [
        self.colmap_path,
        "mapper",
        "--database_path", f"\"{database_path}\"",
        "--image_path", f"\"{image_path}\"",
        "--output_path", f"\"{output_path}\"",
    ]
    self._run(cmd)
```

#### Метод `run_image_undistorter(image_path, sparse_path, dense_path, max_image_size)`

Выполняет **устранение дисторсии объектива (image undistortion)**. Использует параметры камеры, полученные в ходе SfM, для исправления геометрических искажений изображений. Исправленные изображения сохраняются в директорию `dense_path`. Параметр `max_image_size` ограничивает максимальный размер изображения (по умолчанию 2000 пикселей) для управления потреблением памяти.

#### Метод `run_patch_match_stereo(dense_path)`

Выполняет **плотную стереоскопическую реконструкцию (dense stereo matching)** с применением алгоритма PatchMatch Stereo. Для каждого изображения строится карта глубины. Флаг `--PatchMatchStereo.geom_consistency true` активирует геометрическую согласованность карт глубины между соседними изображениями, что повышает качество реконструкции.

#### Метод `run_stereo_fusion(dense_path, output_path)`

Выполняет **слияние карт глубины (stereo fusion)** — объединяет все карты глубины в единое плотное облако точек. Результат сохраняется в файл `fused.ply` в формате PLY.

#### Метод `run_poisson_mesher(input_path, output_path)`

Выполняет **построение полигональной сетки методом Пуассона (Poisson Surface Reconstruction)**. Принимает облако точек `fused.ply` и восстанавливает по нему замкнутую поверхность в виде треугольной сетки. Результат сохраняется в файл `meshed-poisson.ply`.

### 5.3 Плотная реконструкция — `dense_reconstruction.py`

Файл: `src/dense_reconstruction.py`

Модуль выполняет три следующих этапа после SfM: устранение дисторсии, плотную стереоскопическую реконструкцию и слияние карт глубины.

```python
def main():
    project_dir = Path(__file__).parent.parent / "data"
    images_dir = project_dir / "images"
    sparse_dir = project_dir / "sparse/0"
    dense_dir = project_dir / "dense"
    dense_dir.mkdir(parents=True, exist_ok=True)
    fused_output = dense_dir / "fused.ply"

    colmap = ColmapRunner()

    colmap.run_image_undistorter(
        str(images_dir.resolve()),
        str(sparse_dir.resolve()),
        str(dense_dir.resolve())
    )
    colmap.run_patch_match_stereo(str(dense_dir.resolve()))
    colmap.run_stereo_fusion(str(dense_dir.resolve()), str(fused_output.resolve()))
```

<img width="850" height="434" alt="image" src="https://github.com/user-attachments/assets/9111faf1-2b42-4e65-9776-7737b0526716" />

**Важный момент:** путь к разреженной модели указывается как `sparse/0`, что соответствует первой (нулевой) модели, которую создаёт COLMAP. В случае нескольких несвязных групп изображений COLMAP может создать несколько моделей (`0`, `1`, `2` и т.д.).

Используется `Path.resolve()` для получения абсолютных путей, что исключает ошибки при запуске из различных рабочих директорий.

### 5.4 Полигональная сетка — `meshing.py`

Файл: `src/meshing.py`

Модуль строит полигональную сетку на основе плотного облака точек.

```python
def main():
    project_dir = Path(__file__).parent.parent / "data"
    dense_dir = project_dir / "dense"
    fused_path = dense_dir / "fused.ply"
    mesh_output = dense_dir / "meshed-poisson.ply"

        print("fused.ply не найден! Сначала запусти dense reconstruction")
        return

    colmap = ColmapRunner()
    colmap.run_poisson_mesher(
        str(fused_path.resolve()),
        str(mesh_output.resolve())
    )
```

### 5.6 Графический интерфейс — `main_gui.py`

Файл: `main_gui.py`

Модуль предоставляет полноценный графический интерфейс для управления процессом реконструкции. Реализован с использованием фреймворка PySide6 (Python-привязки Qt6).

#### Класс `ColmapWorker(QThread)`

```python
class ColmapWorker(QThread):
    progress = Signal(int)
    log = Signal(str)
    finished = Signal()
```

Рабочий поток, в котором выполняется обработка COLMAP. Вынесение тяжёлых вычислений в отдельный поток — обязательный паттерн при разработке GUI: без этого интерфейс «замерзает» во время обработки.

Определены три сигнала Qt:
- `progress` — передаёт значение прогресса (0–100) для обновления прогресс-бара.
- `log` — передаёт текстовые сообщения для вывода в лог.
- `finished` — сигнализирует о завершении всей обработки.

В конструкторе `__init__` сразу создаются все необходимые директории проекта:

```python
def __init__(self, images_dir):
    super().__init__()
    self.images_dir = Path(images_dir)
    self.project_dir = self.images_dir.parent
    self.database_path = self.project_dir / "database.db"
    self.sparse_dir = self.project_dir / "sparse"
    self.sparse_dir.mkdir(exist_ok=True)
    self.dense_dir = self.project_dir / "dense"
    self.dense_dir.mkdir(exist_ok=True)
```

#### Метод `run()` класса `ColmapWorker`

```python
def run(self):
    colmap = ColmapRunner()

    steps = [
        ("Feature extraction", lambda: colmap.run_feature_extractor(...)),
        ("Matching",           lambda: colmap.run_matcher(...)),
        ("Mapping",            lambda: colmap.run_mapper(...)),
        ("Undistortion",       lambda: colmap.run_image_undistorter(...)),
        ("PatchMatch Stereo",  lambda: colmap.run_patch_match_stereo(...)),
        ("Stereo Fusion",      lambda: colmap.run_stereo_fusion(...)),
        ("Poisson Meshing",    lambda: colmap.run_poisson_mesher(...)),
    ]

    for i, (name, func) in enumerate(steps, start=1):
        self.log.emit(f"🔹 {name}...")
        func()
        self.progress.emit(int(i / total * 100))

    self.finished.emit()
```

Все семь этапов реконструкции оформлены как список пар `(название, функция)`. После выполнения каждого этапа обновляется прогресс-бар (≈14% → 28% → ... → 100%). По завершении последнего шага в лог выводится путь к готовому файлу `mesh.ply` и испускается сигнал `finished`.

#### Класс `MainWindow(QDialog)`

Главное окно приложения. UI загружается из файла `ui/menu.ui`, созданного в Qt Designer — это позволяет разделять логику приложения и его визуальное оформление.

```python
loader = QUiLoader()
ui_file = QFile("ui/menu.ui")
ui_file.open(QFile.ReadOnly)
self.ui = loader.load(ui_file, self)
```

#### Метод `select_folder()`

```python
def select_folder(self):
    folder = QFileDialog.getExistingDirectory(self, "Выберите папку с фото")
    if folder:
        self.selected_folder = folder
        self.model.setRootPath(folder)
        self.ui.treeView.setRootIndex(self.model.index(folder))
        self.ui.plainTextEdit.appendPlainText(f"📁 Выбрана папка: {folder}")
```

Открывает стандартный диалог выбора директории. После выбора папки инициализируется `QFileSystemModel`, которая отображает содержимое выбранной директории в виде дерева файлов (`treeView`).

#### Метод `on_tree_item_clicked(index)`

```python
def on_tree_item_clicked(self, index):
    file_path = self.model.filePath(index)
    suffixes = (".jpg", ".jpeg", ".png", ".bmp", ".gif")
    if file_path.lower().endswith(suffixes):
        pixmap = QPixmap(file_path)
        pixmap = pixmap.scaled(
            self.ui.previewLabel.width(),
            self.ui.previewLabel.height(),
            Qt.KeepAspectRatio,
            Qt.SmoothTransformation
        )
        self.ui.previewLabel.setPixmap(pixmap)
```

Обработчик клика по элементу дерева файлов. Если выбранный файл является изображением (проверяется расширение), оно загружается и отображается в области предпросмотра (`previewLabel`) с сохранением пропорций. Для масштабирования используется `Qt.SmoothTransformation` — алгоритм бикубической интерполяции, обеспечивающий высокое качество изображения.

#### Метод `start_processing()`

```python
def start_processing(self):
    if not self.selected_folder:
        self.ui.plainTextEdit.appendPlainText("❌ Сначала выберите папку!")
        return

    self.worker = ColmapWorker(self.selected_folder)
    self.worker.progress.connect(self.ui.progressBar.setValue)
    self.worker.log.connect(self.ui.plainTextEdit.appendPlainText)
    self.worker.finished.connect(lambda: self.ui.plainTextEdit.appendPlainText("🎉 Все этапы завершены!"))
    self.worker.start()
```

Запускает обработку. Перед запуском проверяется, что папка выбрана. Создаётся экземпляр `ColmapWorker`, сигналы которого подключаются к элементам интерфейса: сигнал `progress` обновляет `progressBar`, сигнал `log` добавляет строки в `plainTextEdit`. После вызова `worker.start()` обработка происходит в фоновом потоке, не блокируя интерфейс.

## 6. Описание полного пайплайна обработки

Весь процесс генерации 3D-модели состоит из шести последовательных этапов:

```
Фотографии
    │
    ▼
[1] Feature Extraction
    Извлечение ключевых точек (SIFT) из каждого изображения
    │
    ▼
[2] Feature Matching
    Поиск совпадений между всеми парами изображений
    │
    ▼
[3] SfM Mapping
    Разреженная реконструкция: положения камер + разреженное облако точек
    │
    ▼
[4] Image Undistortion + PatchMatch Stereo + Stereo Fusion
    Плотная реконструкция: плотное облако точек (fused.ply)
    │
    ▼
[5] Poisson Meshing
    Построение полигональной сетки (meshed-poisson.ply)
    │
    ▼
[6] PLY → GLB Conversion
    Конвертация в формат для веб и универсальных просмотрщиков
    │
    ▼
Готовая 3D-модель (.glb)
```

**Этапы 1–3** выполняются модулем `main.py` или через GUI (`main_gui.py`).

**Этапы 4** выполняются модулем `dense_reconstruction.py`.

**Этап 5** выполняется модулем `meshing.py`.

**Этап 6** выполняется скриптом `converter_ply_to_glb.py`.

## 7. Структура директорий проекта

После полного выполнения всех этапов директория `data/` приобретает следующий вид:

```
data/
├── images/                   # Входные фотографии объекта
│   ├── IMG_0001.jpg
│   ├── IMG_0002.jpg
│   └── ...
│
├── database.db               # База данных COLMAP (признаки, совпадения)
│
├── sparse/
│   └── 0/                    # Модель разреженной реконструкции
│       ├── cameras.bin       # Параметры камер
│       ├── images.bin        # Позиции камер
│       └── points3D.bin      # Разреженное облако точек
│
└── dense/                    # Результаты плотной реконструкции
    ├── images/               # Исправленные (undistorted) изображения
    ├── sparse/               # Экспортированная модель для undistortion
    ├── stereo/               # Карты глубины (depth maps)
    │   ├── depth_maps/
    │   └── normal_maps/
    ├── fused.ply             # Плотное облако точек
    ├── meshed-poisson.ply    # Полигональная сетка
    └── meshed-poisson.glb    # Финальная модель для веб
```

## 9. Требования к входным данным

Для получения качественного результата к входному набору фотографий предъявляются следующие требования:

- **Перекрытие между снимками** — не менее 60–80%. Соседние снимки должны иметь значительную общую область видимости.
- **Разнообразие ракурсов** — фотографии должны быть сделаны с разных позиций вокруг объекта.
- **Чёткость изображений** — снимки должны быть резкими (без смаза движения).
- **Равномерное освещение** — резкие тени и блики снижают качество реконструкции.
- **Форматы файлов** — JPG, JPEG, PNG, BMP.
- **Рекомендуемое минимальное количество снимков** — от 20–30 фотографий для небольшого помещения.

## 10. Результаты работы программы

В результате выполнения полного пайплайна программный комплекс формирует следующие выходные данные:

- **`sparse/0/`** — разреженная 3D-модель с положениями камер и разреженным облаком точек в формате COLMAP.
- **`dense/fused.ply`** — плотное облако точек с информацией о цвете каждой точки.
- **`dense/meshed-poisson.ply`** — полигональная 3D-сетка объекта в формате PLY.
- **`dense/meshed-poisson.glb`** — готовая 3D-модель в бинарном формате glTF 2.0, пригодная для просмотра в браузере, импорта в Blender, загрузки на Sketchfab и использования в веб-приложениях на базе three.js / Babylon.js.
